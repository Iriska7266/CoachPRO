# CoachPRO

Рабочая локальная веб-версия для тренеров и подопечных. JavaScript на клиенте и сервере: React + Vite, Express, PostgreSQL. Мобильные приложения отложены. Репозиторий: https://github.com/Iriska7266/CoachPRO. Рабочая ветка веб-версии — `ilya`.

## Открыть на этом компьютере

- Приложение: **http://localhost:3000**.
- Администрирование БД: **http://127.0.0.1:5050**.
- Для повторного запуска дважды откройте `Запустить CoachPRO.command`, затем `Открыть pgAdmin.command` в этой папке. Оставьте окна терминала открытыми. Если сервер уже запущен, второй экземпляр не нужен.
- Остановка: Ctrl+C в соответствующем окне терминала. Данные сохраняются в `.local/`.

Демо-тренер: `coach@coachpro.local`. Демо-подопечный: `trainee@coachpro.local`. Пароль обоих: **CoachPRO2026!**. Все исходные люди и результаты вымышленные. Тренер также имеет собственную связь с другим тренером для проверки двух режимов.

Вход pgAdmin: `admin@example.com`, пароль — **PGADMIN_DEFAULT_PASSWORD** в локальном `.env`. Это локальное имя входа, письма на этот адрес не отправляются. В дереве уже добавлено подключение **CoachPRO → CoachPRO · локальная база**. Если оно запросит пароль базы, введите **POSTGRES_PASSWORD** из `.env`.

### Посмотреть таблицы в pgAdmin

Откройте сервер → Databases → **coachpro** → Schemas → **public** → Tables. Правой кнопкой по таблице → View/Edit Data → All Rows. Основные таблицы: `users`, `links`, `groups`, `sections`, `metrics`, `entries`, `tasks`, `summaries`.

| Поле соединения | Значение |
|---|---|
| Host | 127.0.0.1 |
| Port | 54329 |
| Maintenance database | coachpro |
| Username | coachpro |
| Password | POSTGRES_PASSWORD из .env |

`coachpro_test` — отдельная база автотестов; её содержимое пересоздаётся тестами. Тестовый пользователь не имеет доступа к `coachpro`.

## Что реализовано

Вход и восстановление пароля, два режима одного аккаунта, приглашения ссылкой/ID/QR, группы и архив, карточки с гибкими разделами и правами, показатели и история правок, быстрый ввод с офлайн-очередью, история результатов, графики и сравнение с целью/планом, тренировки онлайн и очно, упражнения и подходы, несколько шаблонов, файлы, важные комментарии, запросы отчётов, сводки по расписанию, автоматическая и личная обратная связь, настройки уведомлений.

Сценарии, границы реализации и оставшиеся этапы: [статус проекта](docs/project-status.md), [план по исходному файлу](docs/implementation-plan.md). Подтверждение респондентами, командой и двухнедельный пилот ещё предстоят.

## Разработка на другом компьютере

Требуются Node.js 24+, pnpm 11.25.0. На текущем компьютере launcher использует установленный runtime Codex, если обычного Node.js нет.

```sh
pnpm install --frozen-lockfile
node scripts/setup-env.js
pnpm dev
```

`setup` создаёт случайные локальные секреты. `dev` запускает настоящий PostgreSQL 18.4 через embedded-postgres, создаёт изолированную тестовую базу, применяет SQL-схему, добавляет демоданные один раз и запускает веб-сервер. Docker для этого не нужен. Существующие данные не пересоздаются.

Для pgAdmin отдельно требуется Python 3.12+:

```sh
python3 -m venv .local/pgadmin-venv
.local/pgadmin-venv/bin/python -m pip install pgadmin4==9.18
node --env-file=.env scripts/pgadmin.js
```

На этом компьютере pgAdmin уже установлен. Python используется только инструментом pgAdmin; приложение полностью на JavaScript.

### Сборка и окружение

`pnpm build` создаёт `dist`. `PREVIEW_BUILT=1 pnpm dev` запускает собранную версию локально вместе с PostgreSQL; service worker кеширует оболочку после первого открытия. Полный офлайн-режим всех экранов не реализован: очередь предназначена для быстрого ввода.

Для отдельного PostgreSQL задайте `DATABASE_URL` и `TEST_DATABASE_URL`. В этом случае `dev` не поднимает встроенную базу. `compose.yaml` — альтернативный PostgreSQL 17 на порту 5432 и pgAdmin на 5050; одновременно с локальным pgAdmin его запускать нельзя. В Docker pgAdmin подключается к host `db`, port `5432`. Docker-вариант на этом компьютере не проверялся.

Для внешнего размещения нужны постоянный PostgreSQL, `DATABASE_URL`, `NODE_ENV=production`, корректный HTTPS `APP_ORIGIN`, обратный прокси к 127.0.0.1:3000, SMTP, резервные копии БД и `.local/uploads`. `pnpm start` обслуживает собранный клиент. Серверные cookie в production требуют HTTPS. Демоданные создаются только локальным `dev`, а не `start`.

Без SMTP локальное восстановление пароля пишет письмо в `.local/mail`; в production восстановление возвращает ошибку настройки. Настройки SMTP и VAPID описаны в `.env.example`. Web Push требует разрешения браузера и доступного push-сервиса; реальная доставка пока не проверена. Планировщик работает, пока запущен сервер.

## Структура

- `app/` — интерфейс, IndexedDB, service worker.
- `server/` — API, права, расчёты, планировщик, SQL.
- `scripts/` — запуск, окружение, pgAdmin.
- `tests/` — расчёты и API с отдельной PostgreSQL.
- `docs/` — архитектура, инструкции, план и протокол пилота.
- `.local/` — локальные БД, файлы, письма, pgAdmin; исключена из Git.

`.env` содержит секреты и также исключён из Git. Перед очисткой `.local` сделайте резервную копию: там находятся реальные данные локального приложения.
