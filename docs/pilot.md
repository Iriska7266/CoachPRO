## Прототип: 3–5 респондентов

Попросите без подсказок: добавить зарегистрированного подопечного, пригласить нового, создать очную тренировку с двумя подходами, записать результат, найти динамику и прочитать обратную связь. ## Пилот: 5–8 тренеров, две недели

Перед стартом согласуйте способ хранения данных и участия, назначьте контакт для ошибок. Создайте настоящие аккаунты вместо использования демо. Зафиксируйте исходное время подготовки сводки и долю вовремя заполненных результатов за сопоставимый период. На 7-й и 14-й день соберите короткое интервью.

| Гипотеза / ориентир из документа | Как измерять |
|---|---|
| Сводка требует вдвое меньше времени | Парные замеры одного тренера до/после; медиана и индивидуальные изменения |
| ≥70% записей только в приложении | Опрос + сверка журнала; всего результатов и сколько без дублирования в другой системе |
| ≥60% подопечных смотрят графики и понимают динамику | Наблюдение/опрос: открыть график, назвать направление и причину; не считать простое наличие страницы доказательством |
| Быстрая запись ≤15 секунд | `entries.elapsed_ms` + наблюдение; медиана, 90-й процентиль, доля укладывающихся |
| ≥50% тренеров продолжают на второй неделе | Число участников с полезным действием на 8–14-й день / число начавших |
| Своевременное заполнение +25% | До старта уточнить: относительный рост или процентные пункты; одинаковые критерии срока до/после |
| Динамика совпадает с оценкой тренера ≥8 из 10 | Десять реальных обезличенных случаев, независимая оценка тренера до показа алгоритма |

Локальные UI-замеры 5,4 и 10,3 секунды на демоданных показывают работоспособность таймера, но не доказывают достижение цели для пользователей. Автоматического продуктового трекинга просмотров и удержания пока нет: в пилоте это журнал и опрос, а не выдуманная аналитика.

SQL для времени ввода (Query Tool pgAdmin, фильтр дат заменить сроками пилота):

```sql
SELECT count(*) AS entries,
       round((percentile_cont(0.5) WITHIN GROUP (ORDER BY elapsed_ms)/1000)::numeric, 2) AS median_seconds,
       round((percentile_cont(0.9) WITHIN GROUP (ORDER BY elapsed_ms)/1000)::numeric, 2) AS p90_seconds,
       round(100.0*count(*) FILTER (WHERE elapsed_ms<=15000)/nullif(count(*),0), 1) AS within_15_percent
FROM entries
WHERE elapsed_ms IS NOT NULL AND deleted_at IS NULL
  AND created_at >= '2026-11-01' AND created_at < '2026-11-15';
```

Даты выше — пример, не утверждённое расписание. Исключите демоаккаунты при работе в общей базе или используйте чистое окружение пилота.
