# Архитектура CoachPRO 0.1

Дата: 19 октября 2026. Реализованная архитектура; командное утверждение ожидается. Исходный Word прочитан из Downloads, текст сохранён в `source/product.txt`. Выбор JavaScript и веба имеет приоритет над предложениями TypeScript/Expo в исходнике.

## Компоненты

React 19 + Vite 7 → HTTP JSON API Express 5 → PostgreSQL. Браузер и API имеют один origin. Node.js 24. Запуск локальной БД через embedded-postgres; это PostgreSQL, доступный обычному pgAdmin. Файлы хранятся на диске `.local/uploads` и выдаются через авторизованный API. Сводки/напоминания проверяются сервером раз в минуту.

## Модель

| Таблица | Назначение |
|---|---|
| users | Аккаунт, публичный ID, scrypt-хеш пароля, JSONB-настройки |
| sessions / password_resets | Хеши токенов, срок действия, отзыв при смене пароля |
| links | Направленная связь тренер → подопечный, архив, ручная динамика |
| invitations | Одноразовые приглашения с хешем токена, адресатом/группой, сроком |
| groups / group_members | Группы тренера и включённые связи |
| sections | Гибкие разделы: текст, видимость, разрешение правки, версия |
| metrics | Показатели: единицы, направление цели, целевое значение/дата, порог, владелец, версия |
| entries | Значение, время замера, автор, задача, idempotency ID, длительность ввода, мягкое удаление |
| tasks | Тип, время/место, статус, версия, JSONB-массив упражнений и подходов |
| templates | Частные шаблоны задач/структуры карточки в JSONB |
| audit_events | Снимки до/после, сущность, автор, время |
| attachments | Метаданные файла, задача/упражнение/подход, имя в файловом хранилище |
| important_comments | Важные комментарии к тренировкам |
| report_requests | Срок, описание, ответ подопечного |
| summary_schedules / summaries | Частота, следующий запуск, данные сводки, публикация, личный комментарий |
| notifications / push_subscriptions | Уведомления по режиму и подписки браузера |

Карточка — агрегат одной `links`, отдельной таблицы `cards` нет. Упражнения и подходы сохраняются единым JSONB задачи: атомарная версия защищает одновременные правки. Удалённые упражнения остаются с флагом и пометкой автора. Групповое назначение создаёт независимую задачу для каждого участника. Полная схема — `server/db/schema.sql`; миграция идемпотентная, для первого релиза без истории номеров миграций.

## Права и данные

Роль определяется конкретной связью, а не только переключателем интерфейса. Активная связь и принадлежность проверяются на сервере. Подопечный не получает скрытые разделы, соответствующие измерения и приватную историю. При чтении старых сводок заново применяется текущая видимость показателей. Архив скрывает карточку из рабочего списка; выход из связи закрывает доступ обоим участникам.

Пароли хешируются scrypt, сессии HttpOnly/SameSite, production Secure. Запросы изменения требуют X-CoachPRO; CORS не открыт. Есть ограничение попыток входа, проверка входных данных Zod, параметризованный SQL. Файлы до 25 МБ: разрешённые MIME + начальная сигнатура, принудительное скачивание и проверка связи. Антивирусное сканирование файлов ещё не подключено.

## Офлайн и конкуренция

IndexedDB хранит очередь быстрых записей по user ID и кеш доступных карточек. После восстановления связи клиент проверяет текущий аккаунт и повторяет запрос с тем же operation_id. Уникальность author_id + operation_id предотвращает дубли, изменение содержимого повторной операции отклоняется. Удаление кеша браузера удалит ещё не синхронизированную очередь. Полный офлайн-редактор тренировок и файлов не входит в эту версию.

Разделы, метрики и задачи используют version и транзакцию с блокировкой строки; устаревшая версия возвращает 409. Для разделов/метрик доступен откат снимка, для результатов — восстановление мягко удалённой записи.

## Расчёты

Динамика сравнивает первое и последнее неудалённые измерения по времени. Направление «снижение» инвертирует оценку, «цель» сравнивает расстояние до цели. Последние три значения в пределах порога дают плато. Порог по умолчанию 1%, при нулевой базе процент не рассчитывается. Меньше двух записей — недостаточно данных. Это прозрачная эвристика, её согласие с тренером нужно проверить в пилоте.

План по дате линейный: от первого замера к целевому значению в конце выбранного дня UTC. Сравнение производится на дату последнего замера. Дата и число задаются тренером; превышение цели оценивается по расстоянию до неё. Это организационный ориентир, не медицинская рекомендация.

Периоды сводки полуоткрытые [начало, конец), учитываются выполненные/пропущенные задачи, метрики и просроченные задачи. Автотекст детерминированный, без ИИ. Тренер может сначала проверить текст и добавить личный комментарий или включить автоматическую публикацию. Планировщик защищён от одновременного запуска в одном процессе; ключ периода исключает повторные сводки. Для нескольких серверных процессов потребуется отдельный worker с распределённой блокировкой. После долгого простоя не создаются все исторические пропущенные периоды.

## Хранение и эксплуатация

Разработка: `.local/postgres`, `coachpro`, localhost:54329. Тесты: `coachpro_test`, отдельная роль без CONNECT к основной БД. Тестовый скрипт отказывается работать с URL, не оканчивающимся на `_test`.

Локальный режим рассчитан на один сервер. Перед размещением: versioned migrations, резервные копии с проверкой восстановления, постоянное файловое хранилище, HTTPS, SMTP и проверка реальной доставки уведомлений. Эти работы ещё не выполнены, публикация сейчас не запрашивалась.
